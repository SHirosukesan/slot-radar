# スコアの考え方

**現在（Phase 0）、スコア計算は実装していません。** 本格実装は Phase 5。

## 原則（仕様 5章）
1. 「店舗の強さ」「設定狙い」「ハイエナ」「イベント実績」「穴場候補」「狙いやすさ」「移動効率」は**別々の概念**。根拠なく 1 つに合成しない。
2. 根拠・重み・検証データが足りなければ **未評価**（0 点にしない）。
3. 母数が少なければ **暫定**、欠損が極端なら **評価保留**。
4. 出典・母数・期間・計算モデルの版を必ずスコアと一緒に保存し、画面で説明できるようにする。
5. 条件の違うサイトの数値を平均しない。解消できなければ出典付きで併記し保留。
6. イベント名だけで加点しない。「出玉 ≠ 設定確定」「平均差枚 ≠ 期待値」。
7. 店舗全体と機種別で信頼度を別管理。人気機種の欠損を検知する。
8. 期間は 30 日 / 90 日 / 1 年。新しいデータを重く。
9. 開催前の予測はスナップショット保存し、後から書き換えない。
10. AI の自動重みと個人のカスタム重みを切り替え可能にし、両方を別保存。

## 表示ルール
| 状態 | 表示 |
| --- | --- |
| データなし | `— / 未評価` |
| 母数不足 | 数値 + `暫定` |
| 欠損過多・矛盾 | `評価保留` |
